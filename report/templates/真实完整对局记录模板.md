# 真实完整对局记录模板

用途：补全报告6.4，供 E 按 B/C 的原始日志整理。**此文件为空白记录规范，不是已发生的游戏。** 最终至少有一场由真实 API 生成且正常结束的对局，不能以人工规则示例、片段或多局拼接替代。

## 1. 版本与来源

| 字段 | 实际值 |
|---|---|
| game_id / seed | 待填写 |
| 选择该局的方法与时间 | 待填写；如“冻结后最早完整且日志齐全的一场” |
| 开始/结束时间（含时区） | 待填写 |
| 程序 commit / 规则版本 | 待填写 |
| DeepSeek 模型标识、请求参数、日期 | 待填写 |
| 四套 Prompt 版本 / 小模型版本 | 待填写 |
| events / calls / summary 原始路径 | 待填写 |
| 真实 API / stub / 降级混用情况 | 待填写；有角色 stub 则不能作为全模型代表局 |
| 完整视频 / 短片路径、时长与录制方式 | 待填写；区分实时录屏与日志回放录制 |
| 记录人 / 技术核对人 / 日期 | 待填写 |

## 2. 初始化（报告观察者可见，不传给玩家）

填写1—6号真实身份、起始存活状态和各自权限；核对2狼1预言家3平民。记录事件ID，不依据发言反推身份。说明原始身份由何种 seed/规则生成。

## 3. 逐夜记录：直到游戏真实终止

每一个夜晚均填写：两狼各自提案及 event_id；是否分歧；一轮协商内容和双方最终提案；若仍分歧，规则随机裁决与有效提案集合；预言家查验目标、结果及私有范围；夜间结算死亡者；结算后的存活集合、W/G 与是否终局。同夜死亡的预言家查验保留但不擅自公开。

| 昼夜 | event_id | 行动者 | 类型/私有内容或结果 | 可见范围 | 合法性/规则结果 | 关联调用ID |
|---|---|---|---|---|---|---|

**不要把夜间私有 reason 放进白天公开发言表。** 狼队私密协商与规则随机裁决分别记，不能把后者写成“达成一致”。

## 4. 全部公开发言及小模型结果

逐条保留每个存活玩家的公开文本原文，不能只摘“精彩发言”；原文很长时可放附录逐条列出并在正文链接。分类记录必须来自 A 的真实调用，未返回则写失败，不能人工补标签后称为模型输出。

| 昼夜 | 发言event_id | 玩家 | 公开原文（完整） | 预测主标签 | 实体 | 分数状态 | 模型版本/调用ID |
|---|---|---|---|---|---|---|---|

对其中至少一条，另记录“后续代理agent_id—调用ID—可见事件ID—真实输入中原文与标签的位置”。不把后续投票相似视为模型必然使用标签的证据。

## 5. 全部正式投票与结算

| 昼夜/首投或重投 | event_id | 投票人 | target | 有效/无效及原因 | 关联真实调用 |
|---|---|---|---|---|---|

每次投票后写：应投票存活者、有效票数、各候选得票、无效票、平票候选集合、是否重投、重投合法目标限制、最终放逐者/无人放逐。随后写 W/G 与胜负检查。不要把 `vote_intent` 当作正式票。

## 6. 终局与全部调用

- 最后 event_id、终局原因、胜方，或失败/超限的真实状态。
- 昼夜数、实际应分类发言数、首轮成功/重试/最终失败数。
- 玩家、主持、评审的全部 API 调用数；失败、重试和固定主持词兜底。
- 输入/输出及计价子类 token、缺失用量、价格日期、估算费用和币种。
- 每次异常的事件与处理；不因为最终获胜就删除中途错误。

## 7. 视频与画面关联

| 原片时间点 | 短片时间点（如入选） | event_id/调用ID | 屏幕显示与原始记录 | 核对人 |
|---|---|---|---|---|

至少核对建局、完整关键发言及分类、后续输入证据、投票裁决与终局。短片可以删除等待时间，但不改写行动、不拼接另一局。画面截图注明是否回放。

## 8. 本局可支持的结论与局限

写清该局实际证明了哪些链路、哪些部分仍缺证据、是否有兜底或降级。单局仅说明该配置的一次运行，不推导稳定胜率或普遍决策能力。填写完成后由 B/C 核对真实过程，A 核对分类，D 核对视频，E 统一写入报告并更新 G01/M02/I02/V02。
