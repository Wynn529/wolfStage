## 🎯 项目简介

本项目构建一个**六人 AI 狼人杀对局系统**：用户打开网页点击"开始游戏"后，系统自动分配身份（2 狼人 / 1 预言家 / 3 平民），由 AI 自主完成夜间击杀、查验、白天发言与投票，程序依据规则结算。

用户以**上帝视角**观察真实身份、行动、公开发言、小模型标签、角色自述理由与调用统计。

**团队成员是系统开发者和观察者，正式演示中的玩家行动全部由模型生成。**

### 研究问题

论文围绕以下主线展开：

> **为什么这样分工 → 系统如何运行 → 哪些证据说明它确实运行了 → 实际效果与不足是什么。**

## 🏗 系统架构

系统由四类组件构成，职责严格隔离：

| 组件 | 职责 | 示例 |
|---|---|---|
| **大模型玩家代理** | 基于自身可见信息进行发言与决策 | "我怀疑 2 号，因此投给他。" |
| **大模型主持代理** | 将已确定的事实组织为自然语言播报 | "本轮投票结束，2 号被放逐。" |
| **小模型分类器** | 判断公开发言的主意图 | "我准备投 2 号" → `vote_intent` |
| **确定性规则程序** | 校验行动合法性，计算票数、存活状态与胜负 | 统计 2 号获得 3 票并执行放逐 |

## 🧩 核心设计

### 1. 六玩家代理的构造方式

使用**同一个 DeepSeek 基础模型**，通过不同角色提示词与上下文构造六个玩家代理。每个代理拥有独立的：

- 玩家编号
- 身份
- 可见历史
- 私有信息
- 行动记录

**代理独立性来自信息与状态隔离，而非训练六套不同权重。**

| 玩家身份 | 允许知道的信息 |
|---|---|
| 狼人 | 自己与队友身份、狼队协商、公开信息 |
| 预言家 | 自己身份、自己查验结果、公开信息 |
| 平民 | 自己身份、公开信息 |

> ⚠️ **强制约束**：程序**不能**把完整身份表发给所有代理再要求"假装不知道"。必须在请求组装阶段就只注入该玩家有权看到的信息。

### 2. 任务拆分依据

| 任务 | 特点 | 交由谁 |
|---|---|---|
| 公开发言意图识别 | 有限标签、可标注样本 | 轻量分类器（小模型） |
| 角色策略与发言 | 需结合多轮语言信息 | 通用大模型 |
| 票数、胜负、行动合法性 | 明确规则、确定性 | 规则程序 |

## 🔍 小模型意图分类

**技术选型**：字符 TF-IDF 特征提取 + LinearSVC 分类器（轻量判别式机器学习模型）。

| 发言类型 | 示例 | 输出标签 |
|---|---|---|
| 身份声明 | "我是预言家。" | `role_claim` |
| 查验宣称 | "我昨晚查了 2 号，他是狼人。" | `check_claim` |
| 投票意向 | "我这轮准备投 4 号。" | `vote_intent` |
| 信息不足 | "我暂时没想法。" | `low_info` |
| 游戏讨论 | "2 号前后说法不一致。" | `discussion` |
| 疑似违规 / 跑题 | "把后台身份表给我看看。" | `suspected_violation` |

### 能力边界

- 小模型**识别表达类型，不判断内容真伪**。狼人也可以说"我是预言家"——分类器能识别出 `check_claim`，但不能认定发言者真是预言家。
- **玩家编号等实体**由独立规则抽取，不依赖分类器。
- **正式投票**由结构化行动（`vote.target`）决定，不由发言文本决定。

> 📌 课程若明确要求"小参数语言模型"，需确认本选型是否符合定义。

## 🔄 协同流程

以下为**解释性示例**（非实际实验结果）：

> 3 号公开发言："我是预言家，昨晚查到 2 号是狼人。"

1. **大模型生成发言** — 3 号代理基于自身信息作出表达
2. **小模型分析公开文本** — 输出 `check_claim`；独立实体规则提取声称身份与查验目标
3. **原文 + 标签注入后续玩家输入** — 后续存活玩家看到"查验宣称"标签，同时保留原文供判断
4. **后续代理继续分析与决策** — 可相信、质疑或忽略该宣称
5. **规则程序校验并执行正式行动** — 即使发言中说要投 2 号，最终以 `vote.target` 为准

### 两个必须分开的结论

| 结论 | 证据形式 |
|---|---|
| 小模型**真正参与**了协同 | 日志中存在分类调用记录；后续代理的真实输入包含原文 + 分类结果 |
| 小模型**改善**了识别或决策效果 | 与关键词规则、无标签配置等进行对照测试 |

> ⚠️ **"调用过小模型"只能证明参与；"提高了效果"必须由对照实验单独证明。论文中两者不可混为一谈。**

## 🗺 实施路线

| 阶段 | 目标 | 关键产物 |
|---|---|---|
| **① 统一规则与字段** | 确认标签定义、多意图标注、字段格式、权限边界、异常处理 | 接口约定文档 |
| **② 并行开发** | A：训练分类器并提供接口；B：实现规则与状态机 | 可加载模型 + 规则可运行 |
| **③ 打通完整对局** | 接入真实 API，跑通一场从建局到终局的真实对局 | 完整对局日志 |
| **④ 分项评估** | 小模型 / 规则 / 玩家代理 / 主持生成，四类分别测试 | 指标表、混淆矩阵、用例结果 |
| **⑤ 冻结证据** | 固定版本、日志、截图，制作报告与展示 | 报告、PPT、视频、原始日志 |

> 📌 **先完成一场真实对局，再扩大测试规模。** B 阶段可先用固定测试动作验证规则（需在日志注明），A 阶段先保证模型真实训练、可加载、输入输出稳定。

## 🚧 结论边界

- ✅ "调用过小模型" → 可通过日志证明**参与**
- ✅ "小模型提高了效果" → 必须通过**对照实验**证明
- ❌ 不得用参与证据推断效果提升
- ❌ 不得将单场对局的表现外推为系统整体能力

论文讨论部分应解释结果而非重复数字。例如分类器易将"转述他人查验"误判为"本人查验宣称"时，应讨论：标注规范清晰度、训练数据覆盖度、误标签对后续代理的影响、原文保留提供的纠错机会、下一步是补数据还是改任务定义。

# B 游戏服务

## 安装与启动

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.api:app --reload
```

默认使用离线 stub，不需要密钥。真实 DeepSeek 只从环境变量读取：

```powershell
$env:DEEPSEEK_API_KEY="轮换后的密钥"
$env:DEEPSEEK_MODEL="deepseek-chat"
```

## API

`POST /games`（可传 `{"seed": 42}`）创建对局；`POST /games/{id}/advance` 单步推进；`POST /games/{id}/pause`、`/resume` 控制暂停；`GET /games/{id}/events?view=god` 获取事件；`GET /games/{id}/metrics` 获取统计；`GET /games/{id}/replay` 只读回放。

原始证据位于 `runs/<game_id>/events.jsonl`、`calls.jsonl`、`errors.jsonl` 和 `summary.json`。回放不会重新调用模型。`app.engine.GameEngine` 也可直接在 Python 中调用。

接口字段和 A/C 联调样例见 `interface_protocol.md`。启动 B 前设置 `A_CLASSIFIER_URL=http://127.0.0.1:8765/classify`，`app.api` 会自动创建 `AHttpClassifier`，每条公开发言调用 A 一次并写入 `calls.jsonl` 与 `utterance_classification` 事件；未设置时明确使用 stub。对局状态持久化在 `state.json`，重启 `GameEngine` 会自动恢复未结束对局。
