# 十人局完整发言标注指南（v0.4）

本文件保存用户审核后的十人标注口径；实际预测和标注可能不同，实测范围见evidence/ten_player_v04。六人历史指南保留。主标签、实体真值与真实游戏状态必须区分。完整公开发言/遗言为一条记录，不拆段后分散到训练和测试中。

## 主标签与实体分别标注

主标签优先级：`suspected_violation > check_claim > role_claim > vote_intent > discussion > low_info`。

| 标签 | 标注范围 |
|---|---|
| suspected_violation | 明确越权、篡改规则/他人操作、索取秘密等；正常查询公开信息不属于 |
| check_claim | 本人明确声称完成了具体查验；引用、假设、未来计划不属于 |
| role_claim | 本人明确肯定自称角色；仅否认、他人引用、能力暗示不自动成为肯定自称 |
| vote_intent | 明确肯定/否定/条件投票、改票、撤回、跟票、弃票或投票号召 |
| discussion | 具体分析、提问、明确对象评价，或无更高意图的技能宣称/计划/建议 |
| low_info | 没有上述可支持的信息；纯问号、过麦、无法解析的孤立指代不猜具体意图 |

主标签不限制实体抽取：同一记录可同时保留支持10号、投7号、查验和技能等不同信息。对某个样本而言，没列出的部分实体核对项不自动视为标注为空。

当前TF-IDF/LinearSVC以 `public_text` 为输入、主标签为监督目标；实体规则独立测试。增加 `skill_claims` 标注不会直接让当前SVM学会技能抽取。不得把实体标注效果当成分类模型训练效果，也不得把人工实体真值作为模型推理特征。

## 编号、Markdown与JSON

- 编号范围1—10；“十号”归一化为10，10号不能拆成1号。人数、票数、夜次、概率和日期不当玩家编号。
- **Markdown列表编号 `1.`、`2.` 是结构标记，不是1号/2号玩家。**TP073的“1. 他主动排坑；2. 逻辑自洽。本轮投7”仅保留真正提及的7号、10号；support_target=10、vote_target=7，标签vote_intent。
- 标题、粗体和代码围栏不改变语义；引用/否认/条件等标记不能被无差别清除。原文保存，规范化文本另存，同源格式变体同组。
- JSON字符串仅是公开文本的包装。明确约定的单一 `message` 或 `speech` 字符串为发言正文；外层 `role`、`intent` 既不是身份事实，也不是可直接采用的标签。
- TP084正文“我不是女巫，我投7号”标vote_intent、claimed_role=null、vote_target=7。**外层 `role: witch` 绝不能把否认改成女巫自称。**
- 两个正文键冲突、重复键、嵌套/非字符串内容、未约定的自然语言字段或JSON解析失败时，不猜哪一段是唯一正文。保留原文并标明格式异常，不得默默丢掉否认、条件或越权请求；也不从元数据键抽取身份。

## 本人技能与资源表述

`skill_claims`记录本人明确的救人/毒人/开枪表述。必须同时判断主体、引用范围、否认、条件、时间和指代，不能只搜索一个“我”。

- “女巫救下9吧”“女巫今晚考虑救9号”是向他人提出建议：discussion、player_ids=[9]、skill_claims=[]；不创造“discussion专用实体池”。
- “7号说：我救了9号”仍是他人引用，不记成本人技能。
- “如果我是女巫，我会救9号”是反事实角色假设，不记成当前本人技能计划。
- 可以唯一归属本人的连续句或本人成为主语的座位写法不必机械要求每句都有“我”。例如speaker_id=10，发言“10号是我。昨晚本人救了8号”有明确归属。归属不清则不猜。
- TP082两项分别记录save/8/claimed_done与poison/10/planned，role均为null。TP002明确自称猎人，TP040只暗示能力；两者都保留7号条件开枪，但不认证实际资格。

资源表述采用本轮用户建议的“保留原文核对项”方案：`resource_claim_notes`是**数据审查附注，不是运行接口字段**。TP075保留“药还在”，资源类型与数量未知；不加入无目标含义的 `action=inventory`，也不擅自推断两瓶药都在。TP006、TP098明确说到药剂的地方同步保留证据片段。本轮不扩展真实库存抽取。

## 无信息、弃票与置信度

TP094“他吧，就那个”建议low_info，但这个建议不等于模型已经会正确输出。未校准模型的confidence始终为null，不能承诺某句必定得到指定标签。

`not_expressed_or_unresolved`表示未抽到明确投票意向或无法消歧，不是“玩家没有意向”的事实，更不是弃票。正式投票、过麦、等待操作由B按事件和明确操作处理。真人未选保持等待；若未来增加超时规则，必须另行确认并记录，不能由A的low_info自动触发。

## 长文本与后续实验

保留全文，不默认采用“前150字＋后50字”裁剪，避免丢失中间的否认、改口、引用主体、查验或技能对象，也避免短句被前后重叠拼接。

TP097为84个字符，旧模型实际判discussion，建议标签vote_intent；该已知错误保留为开发回归。它小于200字符，因此这项裁剪无法解释或解决本例。当前实现并没有只读取开头的机制；TF-IDF统计全篇字符n-gram，特征权重和训练覆盖需要通过实验判断。

数据审核后可在训练/开发分组内比较全文TF-IDF基线与新增的分句/位置特征。若考虑投票句加权，必须同时测试否定、引用、条件和改口，不对所有出现“投”的句子机械加权，也不在测试集上挑方案。实体始终从完整有效正文抽取，不从丢失内容的截断文本取所谓完整实体。模型标签不因某个已知样本查表改写。

## 评估与版本

102条已获用户批准作为开发训练材料，全部用于新训练并在分组CV中检查，真实十人发言仍为0。旧测试/探针不混进新训练，原文与格式变体按来源/情境分组，同一真实对局不跨集合。分别报告分类和实体结果、已知回归和新增独立评估。运行入口、清洗及技能解析实现后还需单独验收。
