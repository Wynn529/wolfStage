# C/E 独立测试与人工核验准备

本文件是待执行流程。空表不计样本、不计场次、不计已完成评分。助手已接触A给出的数据，因此助手生成的文本不能直接称为C/E独立盲测数据。

## 新分类测试集

C和E各自独立起草新的公开发言，保留作者、来源、来源组与是否AI辅助的信息；不要改写或复制A现有留出数据来冒充新独立测试。先写文本和人工预期，不查看当前模型预测；A按标签口径审校争议，冻结后再运行模型与同集基线。

候选空表：`tests/c_independent_candidates.csv`。标签沿用当前A的六类英文标签，实体按A当前接口定义填写。`status`使用draft／needs_review／frozen；AI辅助候选必须标明，不算成员独立创作。冻结时保留内容哈希、来源组隔离检查、版本和审校结论。样本量由C/E/A确认，未达到计划数量时报告实际数量。

真实DeepSeek公开发言另存domain_check，记录game_id/event_id与模型版本，避免与人工独立样本或A原有留出集混算。

## 对局质量与规则核验

待取得真实完整局后，从同一game_id的原始events/calls选择样本并固定清单。失败/超限局单独记录，不只挑成功局。先冻结评分口径和抽样清单，再由C和E分别填写各自的表；互相不看对方答案，助手不替代任何一位实际评分人。

评分空表：`tests/c_human_review_template.csv`。每个reviewer、game_id、event_id、criterion一行；`judgment`使用pass／fail／not_assessable，必须附evidence与说明。适用项建议如下：

| criterion | 判断依据 |
|---|---|
| action_legality | 原始动作是否合法，规则程序是否接受/拒绝正确；合法策略不佳不算规则错误 |
| information_boundary | 实际授权输入是否包含未经授权秘密；缺输入证据记not_assessable |
| classification | 按A冻结口径判断原句与标签/实体，模糊项保留争议；分数不当概率 |
| host_factuality | 主持是否忠实于已裁决事实，是否泄露秘密；模板与模型来源分开 |
| ui_fidelity | 页面原文、票数、身份、存活、分类与原日志是否一致 |

两人完成后再对齐，以原始证据和冻结规则仲裁，保留C原判、E原判、分歧及最终理由。分别报告有效样本数、通过/失败/无法判断数与分歧，不能把无法判断算通过。模型评审如使用，单独标为辅助，不替代双人人工评分。

表3/表4/表6等报告材料由实际执行结果生成；当前只有准备文件，尚无正式人工评分结果或新增独立测试指标。
