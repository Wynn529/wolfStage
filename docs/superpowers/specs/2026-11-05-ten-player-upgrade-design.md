# 十人局、多模型与真人参与：修改分工方案

日期：2026-11-05。交付日期：2026-11-09。

本文件汇总本轮已确认需求，供五人并行修改使用。它是设计与分工文档，不代表功能已经实现或测试通过。新版本的范围、截止日期和分工以本文件为准；旧六人局说明及历史实验保留作版本记录。

## 1. 目标与范围

- 固定十人：3 狼人、1 预言家、1 女巫、1 猎人、4 平民，无警长。
- 开局选择全 AI（10 个 AI）或真人参与（1 真人＋9 个 AI）。真人通过运行项目的本机网页操作，不做多设备联机。
- 真人席位可指定身份，也可随机；其余身份仍按角色数量随机分配。
- 每个 AI 席位独立选择模型。支持全部相同、部分重复、全部不同；提供一键统一设置和逐席位调整。
- 多模型接入是交付目标。当前仅 DeepSeek 已确认可用，其他供应商、具体型号及最终数量由文斓确认后登记，不固定六家名单。争取真人局的 9 个 AI 使用不同模型，但不将九种不同模型作为硬性验收条件。
- 保留单步、暂停、继续、日志、统计及回放，并适配新角色与权限。
- 真人不提供行动依据；AI 行动依据是模型主动输出的简短自述，不称为原始内部推理。
- 历史回放采用上帝视角，能查看各 AI 当时保存的行动依据；放大依据正文。
- 11 月 9 日程序、报告、两位主讲人各自的 PPT 和演示视频同步交付。

## 2. 规则

| 项目 | 规则 |
|---|---|
| 狼人 | 存活狼人分别提出击杀目标；分歧时一轮私密协商，再按最终提案多数确定，平票以固定随机种子裁决；目标为非狼存活玩家 |
| 预言家 | 每晚查验一个其他存活玩家，获知狼人/好人；禁止重复查验 |
| 女巫 | 全局一解一毒，每晚最多一药，也可不用；仅首夜可自救 |
| 刀口信息 | 仅在解药尚未使用时获知当晚刀口，使用解药后不再获知 |
| 毒药 | 可毒其他存活玩家；当晚被刀仍可用药，夜间统一结算 |
| 猎人 | 被刀或投票放逐可开枪或放弃；被毒、同时中刀中毒不可开枪；目标为其他存活玩家 |
| 夜间 | 狼人→预言家→女巫→天亮统一结算→符合条件的猎人行动 |
| 白天 | 公布死亡名单，存活者按座位顺序各发言一次，再投票；首日也先经历夜晚 |
| 投票 | 投其他存活玩家或弃票；最高票平票或全部弃票，当天无人被放逐 |
| 遗言 | 仅白天投票出局者有遗言；其他出局者无独立遗言环节 |
| 身份 | 出局不公开身份，猎人发动技能会暴露身份；终局统一揭晓 |
| 好人胜 | 所有狼人死亡 |
| 狼人胜 | 所有神职死亡或所有平民死亡；神职指预言家、女巫、猎人 |
| 判胜 | 完整处理当前死亡与猎人技能后判胜 |

实施默认细则：预言家没有合法查验对象时跳过；首夜使用明确夜晚编号；放逐猎人先开枪再遗言；死亡名单不公开死因；同一轮结算同时满足双方获胜条件则平局。吴林峤在编码前把这些细则写进根目录 rules.md，并以同一版本供其余成员使用。如果采用轮数或预算上限，达到上限记未完成，不算某阵营获胜。

## 3. 分工与代码所有权

### 文斓：多模型、真人接入、配置、最终联调与视频

1. 建立可扩展的模型配置与适配层：供应商、具体型号、接口地址、密钥环境变量名、超时等独立配置。真实 API 形态在确认供应商后按其官方文档验证。
2. 建立席位控制配置：控制类型 human/ai，AI 对应 model_profile_id；开局冻结配置，局中不随意切模型。
3. 多模型共用角色上下文和行动契约，适配层返回统一行动及调用元数据，不复制规则逻辑。
4. 真人服务负责读取本人可见状态、读取待操作、提交操作；真人无需 reason，日志允许为空，不替真人编写依据。
5. 按已确认名单逐个注册、配置、实测模型；密钥不进仓库、日志、截图或录屏。
6. 返回真实模型名、版本、耗时、调用结果和可获得的 token。用量缺失记未知，避免旧实现中丢弃 usage 后记成零。
7. 与吴林峤打通控制器入口，与王玥琳打通配置和真人控件；组织集成验证、冻结版本、录制剪辑视频。

交付：接入模块、配置示例、实际模型验证表、真人服务、联调记录、正式视频和对应原始日志。

### 吴林峤：十人规则、状态机、角色行动与技术答辩

1. 主维护 app/rules.py、app/engine.py、服务公共接线、rules.md 和规则测试。
2. 修改十人角色分配、存活集合与屠边判定；维护药剂、已查验集合、死亡原因、猎人资格。
3. 明确各行动阶段、当前行动人、允许动作、合法目标及放弃条件；新增女巫、猎人和遗言协议。
4. 提供等待真人的状态与恢复机制。AI 返回与真人提交走同一校验和执行入口；文斓负责取得行动，吴林峤负责行动裁决。
5. 保留同局互斥、幂等、游标检查和持久化；刷新、重启不能重复用药或投票。
6. 编写并更新五类角色 Prompt。Prompt 文件与行动枚举由吴林峤统一维护，文斓的适配层负责加载和传输。
7. 事件附角色与规则版本；旧日志用旧版本解释，不按新规则改写六人局历史。
8. 制作本人技术部分 PPT、讲稿并答辩。

交付：规则文档、十人引擎、接口与事件说明、角色 Prompt、规则测试结果、本人 PPT 和讲稿。

### 潘星玥：小模型数据、训练与评估

1. 保留公开发言意图分类职责；实体抽取由规则模块承担，分别测试并准确表述。
2. 优先保留原标签和接口，审查是否覆盖新角色，补女巫救毒、猎人声明、查验、遗言、否认及引用等数据。
3. 实体编号覆盖 1—10 号，重点检查 10 号与多个目标。
4. 公开发言和遗言进入分析；夜间私密行动不作为公开发言输入。
5. 训练测试按来源或对局分组，分别报告旧场景、新角色场景和真实对局样例表现，不提前承诺指标提升。
6. 先交可联调用例和兼容接口，再换新模型；提供算法、样例与指标供吴林峤制作技术 PPT、姚幸怡写报告。

交付：数据及标注说明、模型文件、兼容接口、评估脚本与结果、技术讲解素材。

### 王玥琳：界面、权限呈现与界面测试

1. 开局页支持模式、真人席位与身份、各 AI 模型选择；提供统一设置后逐席调整，不强制去重，不写死模型名单。
2. 十人圆桌、存活状态、阶段、发言、投票和技能结果正常显示。
3. 真人控件按服务端允许动作生成：发言、投票/弃票、狼人提案与协商、查验、用药、开枪/放弃、遗言。无依据输入框。
4. 同步适配客户端、控制器和状态契约：waiting_human 与 waiting_model 必须正确显示；等待真人时停止继续推进。
5. AI 依据采用可展开的独立详情区，标席位、模型和对应行动；正文建议 20—22px、行距 1.6，自动换行，以实际录屏清晰度验收；观战和回放同步放大。
6. 回放显示完整身份和原始 AI 依据，真人只显示实际操作；按规则版本兼容旧日志。
7. 显示按席位和模型的调用统计、失败与耗时；未知用量不显示成零。

交付：运行界面、配置与操作页面、测试记录、正式截图。

### 姚幸怡：全部报告与本人答辩/PPT

1. 独立撰写完整报告，其他成员提供各自实现事实、图、样例和实验结果，无需各自撰写报告章节。
2. 更新问题定义、架构、十人规则、多模型、真人交互、小模型、权限、测试、局限和贡献。
3. 制作本人项目与实验部分 PPT、讲稿，与吴林峤共同衔接答辩。
4. 每人各自交付成果，不增加统一材料汇总岗位；最终程序联调由文斓组织。

建议答辩分段：吴林峤讲架构、规则、接入、隔离、小模型技术与协作链路；姚幸怡讲目标、功能概览、贡献、演示衔接、实验、局限和总结。页数由两位主讲人按讲解需要分配，沿用现有统一模板。

## 5. 信息隔离、异常与恢复

- 全 AI 模式允许现场上帝视角；真人模式只返回本人身份、允许的私有信息及公开事件，出局后仍保持玩家视角。
- 真人局结束后开放该局上帝视角历史回放。未结束时不能通过事件、原始状态、调用详情、回放或日志下载读取其他身份、依据及技能秘密。
- 权限由服务端会话绑定，不能仅靠隐藏按钮或接受任意 view/player_id 参数控制。此范围保护网页操作，不承诺抵御本机用户直接读取服务器文件。
- 给 AI 的上下文同样按席位过滤；全 AI 使用相同模型也各有独立上下文，不能共享私有记忆。
- 真人与 AI 均可读取同一公开小模型分析；不向真人泄露其他 AI 的私密自述依据。
- 模型错误与非法输出有限重试，仍失败则停稳并记录；明确重试不能造成重复行动，不能悄悄换模型或用预设剧情顶替。
- 重试同一操作、刷新和重启不重复消耗技能；等待真人状态可以恢复，重复提交返回原结果或明确冲突。
- 日志按实际尝试记调用，真人操作不算模型调用。统计显示实际供应商和型号，不以角色 Prompt 数量冒充模型数量。

## 7. 验收清单

### 规则与恢复：吴林峤主责

- 十人身份数量正确；指定真人身份不改变总配比；随机分配可复现。
- 重复查验禁止，无合法目标可跳过。
- 首夜自救、后续禁止自救、每晚最多一药、药剂耗尽、女巫当晚被刀仍可行动。
- 猎人刀杀/放逐、毒杀、同时刀毒、开枪与放弃；判胜等待技能结算。
- 投票弃票/平票、放逐遗言、其他出局无遗言；两种屠边、清狼和同时达成条件。
- 刷新、重复提交、暂停继续及重启后不重复执行行动。

### 接入与真人：文斓主责

- 模型名单由实际完成情况记录，每个最终纳入的型号有真实成功调用证据。
- 同模型、部分重复、多模型混配均能配置；模型上下文互相隔离。
- 新角色行动通过统一协议校验；已接模型能在同局实际行动。
- 真人狼/预言家/女巫/猎人/平民分别以定向场景测试，真人不填写依据。
- 日志、异常、用量与实际尝试一致，未知值明确标识。

### 界面与权限：王玥琳主责，文斓/吴林峤共同配合

- 真人非法目标、过期操作、重复点击、刷新和等待状态有明确反馈。
- 修改 URL 或视角参数也无法在真人未结束局读取上帝数据；回放/下载/统计详情一并检查。
- 全 AI 观战与终局回放均能显示放大的 AI 依据；真人无伪造依据。
- 十人事件与旧六人回放按版本正确显示；小模型、模型统计可核对。

### 小模型：潘星玥主责

- 新旧场景分别评估，类别指标与错误案例可追溯；1—10 号实体测试通过。
- 保存数据版本、模型版本、评估结果与运行方式，不把规则抽取写成训练模型能力。

### 最终证据：文斓组织，各自负责真实性

- 至少一场全 AI 多模型混战、一场真人参与完整局，保存同局完整事件与调用日志。
- 不要求单局自然出现所有技能；技能定向录制标明功能测试，不拼成虚构完整局。
- 少量对局用于功能验证，不据此宣称模型强弱排名。
- 正式报告、PPT、视频标明新版本和对应 game_id；旧六人素材仅用于历史说明。
- 视频展示配置、真人交互、小模型协作、终局统计、上帝回放及放大的行动依据；验收实际播放可读性。

## 8. 模型登记方式

最终供应商名单、具体型号和数量由文斓确认后维护在运行配置与验证表中，当前不预填承诺名单。DeepSeek 已确认可用，但新版本仍需进行协议联调。每条验证记录包含供应商、实际型号、状态、验证日期及对应测试/对局标识；密钥仅记环境变量位置。不同供应商和不同模型分别统计；同型号不同角色 Prompt 仍视为同一基础模型。

本方案不包含自动注册账号、付费请求执行或功能实现；这些由后续开发与实际验证产生证据。
