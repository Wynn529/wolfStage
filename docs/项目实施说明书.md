# 大小模型协同狼人杀：15 天实施说明书

版本：2026-10-23。交付日：2026-11-07。计划周期：10 月 24 日至 11 月 7 日，共 15 天。

## 1. 交付目标与判定标准

交付一个可在本地浏览器运行的 6 人文本狼人杀系统。六名玩家全部由 DeepSeek API 驱动的角色代理自主发言、击杀、查验和投票；主持服务自动推进流程。系统支持一键运行、暂停、单步、按原始日志回放。上帝视角实时展示身份、行动、自述理由与调用统计。

课程要求的小模型必须是实际训练并参与推理的模型：它分析每轮公开发言，将意图标签交给主持服务和所有存活玩家代理。规则程序独立处理合法性、计票和胜负；大模型负责角色决策和主持语言。报告必须分别说明三者贡献，不能把规则程序称为“小模型”，也不能把三套角色提示词称为三个独立训练的大模型。

验收时需同时拿出：可运行程序、训练脚本与模型、数据划分、版本化提示词、至少一场未经改写的完整 API 对局、按场次的大小模型调用统计、测试台账、报告、PPT、完整版视频与答辩短片。演示对局若角色 API 调用失败而改用预写行动，应标记为失败场，不算“全部模型参与”的证据。

## 2. 游戏规则，先固定再开发

1. 六个玩家编号 1—6，随机种子决定身份：2 狼人、1 预言家、3 平民。两狼互知；预言家和平民只知自己的身份。主持服务保存全局真相。所有角色能看公开发言与小模型给出的公开发言标签，但不得读取别人的私密理由、行动或身份。
2. 首轮从夜晚开始。两狼分别给出击杀目标和简短理由；若不同，再共享彼此提案并私密协商一轮。仍不一致时，由固定随机种子在两个有效提案中选一个，日志明确标记“规则裁决”，不得伪称达成共识。狼人不得击杀狼队友。
3. 预言家每夜查验一名存活的其他玩家，私下得到“狼人/非狼人”。同夜被击杀仍可完成该夜查验。首夜没有公开发言，角色理由应诚实表达证据不足，不强迫编造“某号像预言家”。
4. 天亮宣布死亡者，不公布身份。存活玩家按编号各发言一次。发言含公开文本和独立的自述理由；只有公开文本进入其他角色的上下文。预言家可尝试隐晦传递信息并规避击杀，但这只是策略目标，不能保证成功。
5. 发言后所有存活玩家各投一名其他存活玩家。最高票者放逐；平票时仅在平票者中重投一次，仍平票则无人放逐。所有票、弃权或无效票都入日志；无效票不计入有效票数。投票意向可先由小模型从文本识别，但最终投票目标以角色返回的结构化行动及规则校验为准。
6. 狼人全部出局则好人胜；存活狼人数不少于存活非狼人数则狼人胜。每次夜间死亡和放逐后检查。为防异常无限循环，最多 8 个昼夜；达到上限而无胜方记为未完成，不计入胜负正确率的分母。
7. “悍跳”只在赛后根据真实身份和公开身份声明推导；对局中不得把这项真相标签发给其他玩家。违规、跑题等小模型预测只作为提醒信号；阶段权限、有效投票和胜负以规则程序为准。

上述规则写入 `rules.md` 并在第 3 天前冻结。之后若修改规则，B 同时更新测试期望和报告中的规则版本。

## 3. 技术结构与信息边界

建议 Python 实现：FastAPI 负责游戏引擎和接口，Streamlit 负责网页展示，scikit-learn 负责小模型训练，JSONL 保存逐事件原始日志，CSV/JSON 保存测试汇总。DeepSeek 通过单一适配器调用，API Key 只从环境变量读取，不进入 Git、截图、日志或 PPT。Streamlit 的定时 fragment 可用于轮询状态；暂停只在一次模型调用结束后的事件边界生效。[DeepSeek 接口](https://api-docs.deepseek.com/api/create-chat-completion/)、[Streamlit 定时 fragment](https://docs.streamlit.io/develop/concepts/architecture/fragments)。

模块分层如下：

```text
Streamlit 上帝视角界面
          ↓ 控制 / 查询
FastAPI 游戏引擎 ── 规则状态机、行动校验、事件日志、统计
     ├─ 小模型适配器：公开发言 → 意图标签/置信度
     └─ DeepSeek 适配器：主持人与 6 个独立角色代理
```

六个玩家代理共用一个基础大模型，但各有独立 `agent_id`、角色提示词、可见历史和私密记忆。主持代理只拿到当前需要播报的事实。上帝视角界面的理由来自角色输出中的 `reason` 字段，是**角色自述的决策依据**，不是可验证的模型内部推理；不把 API 的原始推理字段用作展示或报告证据。

每次角色行动要求返回 JSON，例如 `{"action":"vote","target":3,"text":"我投3号","reason":"3号的身份说法前后不一致"}`。夜间行动分别使用 `kill`、`inspect`；白天使用 `speak`。B 用本地校验检查 JSON 类型、目标是否存活、行动是否符合阶段、文本长度以及秘密是否泄露。无效输出最多重试一次；再失败则暂停该局并记录错误。主持词校验失败可改用固定模板，但须记录兜底。

DeepSeek 官方 Chat Completions 支持 JSON 输出与 token 用量字段；JSON 模式仍可能出现空内容或长度截断，所以本地解析、校验和重试不可省略。模型名、接口参数和单价以调用前的官方文档为准，不把价格写死在程序里。[JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)、[模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)。

## 4. 小模型：数据、训练、参与方式

A 定义六个主意图：`role_claim` 身份声明、`check_claim` 查验结果宣称、`vote_intent` 投票表达、`low_info` 划水、`discussion` 有效讨论、`suspected_violation` 疑似违规或明显跑题。多意图句先按明确的标注优先级定一个主标签，实体另标：玩家编号、声称身份、查验对象、投票对象。例：“我是预言家，3 号是狼”主标签为查验宣称，另记录身份声明和目标 3；不能把“3 号真的为狼”写入公开标签。

基线为字符 n-gram TF-IDF 加 LinearSVC；若需置信度，可做概率校准，或统一使用决策分数并清楚标注其含义。目标约 360 条训练样本和 120 条独立测试样本，六类尽量均衡；训练集可由 A/B/D 起草，测试集由 C/E 独立编写，避免同一模板改几个号码就跨入训练与测试。将真实 AI 对局中的新句子单独作为域外检查，不回填到冻结的测试集。A 保存标注规范、版本、随机种子、分类报告和误判清单。

小模型每遇到一条公开发言推理一次。结果连同原文进入主持服务和之后行动的存活角色代理；低置信度标为 `uncertain`，代理仍能读原文。它不得读取秘密身份，也不得直接作出“谁是狼人”的事实裁决。为了证明协同价值，C 保存一组同样的公开发言，对照“只有关键词规则”和“加入训练后小模型”对意图识别的差别；不能仅展示一两个挑选过的成功例子。

## 5. 大模型角色与主持策略

B 维护四套版本化提示词：狼人、预言家、平民、主持。每套共用硬约束：只使用给定可见信息，返回规定 JSON，`text` 是对局公开话语，`reason` 是上帝视角自述且不传给其他玩家，禁止擅自宣布票数、身份或胜负。

| 代理 | 私有输入 | 决策目标 | 测试重点 |
|---|---|---|---|
| 狼人 | 自己与队友身份、狼队提案、公开记录 | 从可见证据推测高威胁目标；协作击杀；白天为狼队争取投票优势 | 是否刀到有效目标、是否误泄狼队信息、协商是否合规 |
| 预言家 | 自己身份、每夜查验结果、公开记录 | 选择查验目标；用公开发言传达有用线索并控制暴露风险 | 信息有没有被正确利用、是否过早或错误声称查验 |
| 平民 | 自己身份、公开记录及小模型标签 | 比较发言和票型，作出有理由的投票 | 投票理由是否对应公开证据、是否凭空知道秘密 |
| 主持 | 当前已判定事实及允许公开的字段 | 播报阶段、整理发言、提醒违规、赛后复盘 | 不更改规则事实、不剧透、不编造查验或票数 |

不要在 Prompt 中强迫每局出现“预言家成功隐藏”或“狼人刀中预言家”。这些是策略表现，由多局实验评估。首次夜晚无公开证据，可允许基于不确定性的选择。为了节省费用，角色每个行动原则上调用一次；主持人只在阶段转移、违规提示和复盘时调用。默认先试官方较经济的模型档位，并记录模型版本；若输出质量不够，再用同一测试集比较替代档位，不凭主观印象切换。[DeepSeek 官方价格与模型页](https://api-docs.deepseek.com/quick_start/pricing/)。

## 6. 界面操作与录像

C 的页面至少包含：顶部阶段和存活人数；六张玩家卡（上帝视角显示真实身份与存活状态）；中央公开发言时间线；右侧当前行动、自述理由与小模型标签；底部每场调用数、token 数、规则异常数。控制区提供“新建并自动运行、暂停、继续、单步、选择已完成对局回放、导出日志”。暂停在当前 API 调用返回后生效；页面提示“正在等待模型返回”。

D 录一场**真实 API 生成且最终完成**的对局。保留完整录屏和对应 `game_id`、原始日志、模型版本，不剪改行动内容。另剪 2—4 分钟答辩版，重点展示：角色判断 → 小模型分析公开发言 → 主持/玩家使用该结果 → 规则裁决 → 胜负及调用统计。视频若只保留片段，报告仍链接完整日志。现场播放短片；程序和完整视频作为可复核材料。

## 7. 日志、指标与“判得对不对”

B 从第一次完整对局开始自动记录每次调用：`game_id, event_id, phase, caller_type, agent_id, model_name, model_version, prompt_version, input_visibility, attempt, latency_ms, input_tokens, output_tokens, success, fallback, validation_error`。事件另记公开发言、私有行动、规则判定、票数、胜负与自述理由。C 从日志导出每场和总体汇总，不能人工补数字。

每场至少报告：小模型调用次数、大模型玩家调用次数、大模型主持调用次数、可选评审模型调用次数、重试/失败次数、token 用量、估算费用、游戏轮数、胜方、规则断言通过数。项目总体分别报告“不同测试场景数”“完整对局数”“总运行次数”，防止把同一对局重复播放当多次测试。

正确性分四层，不混成一个模糊的“准确率”：

1. **小模型：**冻结测试集上的各类 precision、recall、F1、macro-F1 和实体抽取准确率。
2. **规则：**预设输入与预期阶段、有效票、票数、胜负逐项比较，报告通过率；至少覆盖 30 个规则与异常用例。
3. **角色决策：**公开证据是否支持行动理由、角色可见信息是否合规、行动是否有效，由两人按量表抽样核对；胜负本身不能直接当作个人决策准确率。
4. **主持生成：**事实一致、未剧透、格式合规的比例。可让另一公开大模型 API 辅助复盘，但其结论只作辅助评审，必须与人工抽样核对；评审调用单独计费和计数。

目标运行至少 10 场不同随机种子的完整自动对局和 1 场用于录像的代表性对局；若额度不足，优先完成 1 场可复现的真实对局、规则用例与冻结测试集，并如实报告实际样本量。出现 API 中断、异常兜底或超过 8 个昼夜的局保留日志并单列，不删除失败样本。

## 8. 成本与失败控制

由于 API 预算尚未定，先在配置中设每局最大玩家调用数、主持调用数、输出 token 上限、单次重试上限和累计费用预警值；阈值由实际额度填写，不在说明书中猜具体人民币金额。每场先估算，再启动批量测试。DeepSeek 返回的 usage 是 token 统计依据，实际收费以其账单和实时价格为准。[Token 用量说明](https://api-docs.deepseek.com/quick_start/token_usage/)。

角色 JSON 无效：本地拒绝并重试一次；再次失败则停止本局并记失败。主持词无效：使用固定模板继续，但记录兜底。请求超时：保存当前事件游标，可续跑；绝不把相同事件推进两次。任何外部模型的自述理由都不作为真实身份、规则事实或客观心理推理的证明。

## 11. 报告、PPT、答辩与目录

报告按课程九项写。摘要与背景由 E 统稿；模型与训练由 A/B 提供；系统设计由 B/C 提供；实验由 A/B/C 的真实数据组成；应用价值与局限由 E 写，所有负责人核对。RAG、角色模型独立微调若未做，明确写“未采用”，不能为了填章节伪造。参考资料列实际使用的官方 API、框架文档、游戏规则来源和评价方法。

PPT 建议 10—12 页：目标与场景、责任边界、六代理信息隔离、数据与小模型、角色 Prompt、游戏事件流、界面、真实对局片段、调用统计与规则结果、失败案例与局限、贡献。答辩主讲 E 的重点回答：小模型在哪里真正起作用；三种角色“模型”为什么是角色代理而非三个微调模型；谁决定胜负；如何证明视频没有改写；外部评审模型能证明什么、不能证明什么。

建议交付目录：`app/` 游戏服务与界面，`model/` 训练和模型，`data/` 脱敏样本及划分，`prompts/` 版本化提示词，`tests/` 用例与预期，`runs/` 原始对局与统计，`evidence/` 截图与图表，`report/` 报告，`slides/` PPT，`video/` 两版视频。仓库文件夹一律使用英文名；根目录放记录冻结规则的 `rules.md`、`README.md` 和不含真实密钥的 `.env.example`。API Key 只放本机环境变量。

最终核查：新机器按 README 能启动；完整录像的 `game_id` 能找到原始日志；PPT 与报告的数字可从统计脚本重算；每场大小模型调用数可追溯；公开角色从未收到秘密信息；E 可在答辩时间内讲完并回答上述关键问题。
